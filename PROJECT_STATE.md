It is deliberately ONE value rather than "scored or completed", because every practice under one assignment shares that assignment's scenario, so an assignment is entirely one kind or the other and the caller always knows which. Matching only the right status is also what keeps a graded practice stuck at 'completed' by a scoring failure out of the prune: that is a broken session the student can retry, not a finished practice, and it must never evict a good score. Scoping is otherwise identical (this student, this assignment, kind = practice), the recording-then-row delete order is unchanged, and graded submissions and scored practices are untouched. The student home applies the same per-assignment rule when listing kept practices, and shows "no score" instead of a number for conversation-only entries.
  - Ungraded assignability: an assignment pointing at a rubric-less scenario is practice-only. It offers Practice (text) and Practice (voice + video) and no graded submission path, reads "practice only, not graded" instead of naming a required mode, and explains that there is nothing to submit. Hiding the button is only the UX half: /api/assignment/start independently refuses to create a submission for a rubric-less scenario, which is the actual enforcement and matches how every other session rule in this app is applied server-side. This works under the current pre-Piece-4 model.
  - The create-assignment scenario picker now lists ENABLED scenarios only. In 2a the enabled flag affects the PICKER ONLY; blocking a disabled scenario from being started belongs with 2c and 2d, when disabled candidates actually exist. Nothing else reads the flag yet.
  - End-of-session wording was corrected in both conversation screens so a conversation-only run never promises a score it will not produce ("End this session? ... This practice is not scored" in place of "End this session and see your score?"), along with the matching button label, the dropped-connection message, and the error fallbacks. This is messaging correctness, not polish: the old wording would have been a plain lie on these cases.
  - Known and accepted: an assignment's Required mode is still asked for and stored even for a practice-only assignment, where it is ignored (the student picks the mode each time they practice). Piece 4 repurposes required_mode, so it was left alone here rather than special-cased twice. Also, a practice-only assignment appears in the instructor submissions dashboard with zero submissions forever, since nobody can ever submit it. Harmless, and filtering it out was deliberately left out of scope.
